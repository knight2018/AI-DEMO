# SPEC-009 测试用例

| 编号 | 输入或操作 | 预期 |
| --- | --- | --- |
| SPEC009-TC01 | 初始“手机已连热点但App没画面”；后续补充其他问题答案 | phone_connection 为已知；同义连接问题不再问；多事实回答跳过对应剩余问题 |
| SPEC009-TC02 | 当前明确问手机是否连接，回答“没有”；另一次回答“不知道” | 分别为否定已知、明确未知；保留原话及问题锚点；未知不参与故障条件扩写 |
| SPEC009-TC03 | 无当前问题或多步骤，孤立“没用”；复合问题回答“没有” | 提出澄清；不写入猜测事实或执行结果、不消费未回答问题；下一轮可补清对象 |
| SPEC009-TC04 | 先“有黑屏后的视频”，后“看错了，那是昨天的视频” | 撤回本次时段录像结论，旧事件保留；检索/建议上下文不继续引用旧结论 |
| SPEC009-TC05 | “没连接”纠正为“现在连接好了”；再补充屏保时间 | 更新同一事实，来源轮次可追溯；已知与未知均不重复追问；无关事实保留 |
| SPEC009-TC06 | 指定步骤报告“做了，还是没用” | 记录完成及无改善，不标记解决；下一次建议排除已完成操作；无法执行也不反复要求 |
| SPEC009-TC07 | 撤回先前执行结果；旧建议已存在时纠正事实 | 旧结果不再作为完成依据；旧建议归档失效并要求重新检索；无剩余动作程序转人工 |
| SPEC009-TC08 | 模型超时、伪造quote/字段/操作ID、澄清与更新同时返回、重复字段 | 显式失败，SQLite内容及版本不变；不切换模型，不写半成品 |
| SPEC009-TC09 | 两次同版本提交、刷新/重开、独立新会话、旧v1/v2会话 | 409冲突无覆盖；事实/原话/结果一致；会话隔离；旧行为仍通过原有测试 |
| SPEC009-TC10 | UI查看事实、纠正、操作反馈、下载，文本包含HTML | 展示来源及更新状态、澄清和步骤状态；安全文本渲染；导出和会话匹配 |
| SPEC009-TC11 | DeepSeek真实多轮：重复追问/短答/录像时段纠正/步骤无效反馈 | 逐项核对语义、否定、未知、有效事实与动作排除；保存真实结果 |
| SPEC009-TC12 | 最终代码执行 npm run test:all | 所有历史与新增回归全绿，无失败或跳过才可完成 |

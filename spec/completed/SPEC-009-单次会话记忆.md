# SPEC-009 单次会话记忆

日期：2026-10-23。用户明确授权先补规格及测试用例，再实现重复追问、短句回答、前后纠正、操作结果更新。生命周期见 status.json。

## 范围

在 SPEC-007/008 的新售后会话增加 workflow_version=3，沿用型号确认、真实说明书、BM25+FAISS、受控操作目录及逐字证据校验。已有 v1/v2 会话保持原流程，不在模型失败时降级。仅本次设备与问题的会话记忆，不引入跨会话画像、向量记忆库或自动修改型号。

## 输入、处理、输出

输入为初始主诉、当前问题的回答，以及新入口中的补充/纠正或指定步骤的执行结果。文本模型沿用 AGICTO deepseek-flash；密钥读取 AGI_KEY。

记忆分为：追加保存的用户/助手原话；带来源轮次与引用的事实事件；当前有效事实；已建议操作和执行记录；待澄清内容。事实区分 known、unknown、retracted（撤回后无有效结论）；未出现的字段表示尚未询问，不能与 unknown 混淆。事实键采用核心语义字段及已有知识库追问字段，同义字段统一；不合并不同灯、不同设备软件、历史状态与当前状态。

模型只提出结构化更新，程序校验字段、当前轮原文引用、允许的操作编号、重复字段、澄清互斥及短句绑定后提交。失败不修改会话。事实更新追加事件并关联旧事件，最新有效值参与推理，旧值只用于审计。明确否定为已知事实，纯未知不引入新的检索条件。型号和问题类别在本会话固定，要求更换设备/另一个问题时提示新建会话。

### 四类行为

1. 重复追问：初始主诉提取已有事实；回答时可一次补充多个事实。当前已知和明确未知字段均从剩余问题中排除；同义字段去重。不为凑数增加追问。
2. 短句回答：当前追问作为明确指代上下文；“没有”保留否定，“不知道”记录未知。没有明确对象、复合问题或多步骤下孤立“没用”先澄清，不自动结束问答或把多个状态一起认定。
3. 前后纠正：允许收集、准备建议、已有建议阶段补充/纠正；旧事实被替代或撤回。原始主诉保留审计，但模型上下文与检索使用有效事实；不把被纠正主诉重新作为独立查询。已有建议归档失效，重新检索后才能给新建议，历史引用不冒充当前证据。
4. 操作结果：每条建议映射稳定目录 ID；区分仅建议、用户报告完成、无法执行、撤回结果。记录观察结果与来源，不因“做过了”认定问题解决。再生成时程序排除完成/无法执行的操作；已撤回的执行结果不再作为已完成依据。命中证据中没有未执行可用操作时明确转人工，不重发旧步骤、不伪造新步骤。

输出保留现有逐项问答与建议，增加可查看的本次记忆、补充/纠正输入、操作选择及结果输入。显示待澄清、当前事实与来源、历史变更和执行状态。刷新、SQLite重读和导出保持一致。并发沿用乐观锁，任何失败不半写事实。新建会话无前一会话记忆。

## 测试与完成标准

具体用例见同编号 test-cases 文件。补确定性状态更新、模型契约、API持久化/并发、前端安全渲染测试，并真实调用模型覆盖四类场景。最终代码执行 npm run test:all 全绿，真实调用及网页验证通过后才标记 Completed。模型语义测试仅证明所测样本，不保证任意自然语言的完全理解。

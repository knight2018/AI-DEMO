# SPEC-011 客服聊天与流式回复

日期：2026-10-23。用户授权将说明书售后助手改为聊天窗口，选择在对话内完成，并要求更快、流式显示。只改售后模块，保留评论应用及历史会话/API。

## 设计

主界面为消息列表和单一输入框，设备确认以窗口内弹层完成，追问选项以内嵌按钮发送，操作反馈通过消息中的操作选择完成。信息齐全后自动生成建议，无需用户点击流程按钮。原话、澄清、纠正、已执行操作、来源详情、摘要导出、图片识别和新建会话保留。检索与记忆详情收进可展开面板。

采用 POST + SSE：status 为真实处理阶段，draft 为模型真实增量解析出的概要草稿，state 为已经保存的会话，done 为本轮结束，error 为明确失败。前端读取响应流并立即渲染，不使用定时器伪造打字。草稿清楚标识生成中，完成后以通过校验的结果替换；失败撤去草稿，不保留为有效建议。具体操作及引用沿用完整校验后展示。

先保留原请求逻辑，新增流式入口复用已有路由与持久化。单轮处理锁定发送，新建和刷新恢复已保存会话；断流提示恢复记录，不自动重发，避免重复副作用。连接断开取消未完成后台任务。既有版本冲突和同源请求校验保留。

速度：初始分类与检索后，在完整候选字段范围内并行选择追问与提取记忆，再根据已知事实排除重复追问；当最新检索与有效记忆版本一致时复用该检索用于建议，事实更新后重新检索。状态先返回、真实模型草稿逐步返回；记录首事件、首草稿和总耗时，不承诺固定模型延迟。

## 测试用例

1. SSE 在模型完成前送达状态与概要草稿；中文跨字节、跨事件分块正确解析；无打字定时器。
2. 草稿失败不发布建议、不泄漏内部错误；已保存的用户输入可恢复；断开取消任务；无 done 的结束视为断流。
3. 版本冲突、未确认型号、未知操作、跨域提交被拒绝；不重复写入会话。
4. 信息齐全自动生成建议；澄清时继续聊天；追问选项直接发送；操作反馈绑定明确操作；回复中不重复已执行步骤。
5. 记忆与追问选择并行、同版本检索复用，更新事实后不复用旧检索；所有原回归通过。
6. 聊天气泡、型号弹层、图片识别、详情、导出、刷新恢复、空输入、错误重试、键盘发送及窄屏无溢出。
7. 本机真实接口与页面验证，记录实际首事件/草稿/完成时间；全部必需测试通过后转 completed。

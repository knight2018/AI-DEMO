# SPEC-001 亚马逊商品详情页评论采集与分析

- 创建日期：2026-10-22
- 项目位置：本文件所在项目根目录。
- 生命周期、审批和执行结果：见 `status.json`，不回写本规格原文。
- 当前用途：提交用户审阅；本轮仅整理规格与测试用例，不授权开发。

## 1. 目标与已确认要求

面向 AI 流程搭建专员岗位制作本地可运行的个人演示作品。用户输入真实亚马逊商品地址，通过 Electron 内嵌浏览器采集商品详情页底部可见评论，使用 Python 与 LangChain 分析，展示并导出可追溯的结果。

已确认的主流程：输入商品地址 → 自动采集 → 自动校验与去重 → AI 分析 → 展示与导出。正常流程不设置人工检查或审批关卡；人工仅处理登录、验证码等必要交互和异常。开发验收时进行抽样人工核对，不等于日常操作必须逐条审核。

已确认技术方向：Electron 桌面端、内嵌浏览器与本地网页、Python 后端、LangChain。模型服务按用户既有约定使用 AGICTO，文本分析使用 `gemini-3.8-flash`，密钥只从 `AGI_KEY` 环境变量读取。

## 2. 范围

### 第一版

- 美国站 `amazon.com` 与德国站 `amazon.de` 的商品详情页。
- 采集当前详情页实际展示、正常滚动加载及展开正文后可见的买家评论。
- 商品标题、ASIN、页面可见的当前变体仅作为评论来源上下文。
- 英文和德文评论保留原文，输出中文洞察；任何翻译都单独保存。
- 展示采集进度、原始评论、分析证据与导出入口。

### 不在本规格范围内

- 价格、优惠规则、商品规格分析；“全部评论”跳转与持续翻页。
- 绕过验证码或访问限制、自动输入账号密码、自动购买或发布评论。
- 售后助手、说明书检索、云端部署、定时采集和多任务并发。
- 将竞品声明为五世科技自有商品，或将模拟数据声明为真实评论。

## 3. 建议实现细节与审阅项

以下为便于实现与验收的建议，不冒充已得到逐项确认的用户要求；用户确认本规格后固化。

1. 本地后端采用 FastAPI；SQLite 保存批次、评论和分析状态。
2. 同时只运行一个任务。采集开始后锁定站点、ASIN与可见变体；操作跳转到其他商品或改变变体时暂停，提示重新开始采集，不混入新对象。
3. 一个任务对应一个采集批次。再次采集创建新批次，同一批次内去重，不覆盖历史批次。
4. 评论存在稳定 ID 时，以“站点 + 评论 ID”去重；缺少 ID 时不虚构 ID，保存本地记录标识及 `identity_missing` 标记，不进入自动分析，计入排除数量。不同 ID 的相同文本保留。
5. 正文展开失败、正文为空、评分缺失或不是 1～5 的整数时，该评论标为无效，不进入分析；页面没有日期、国家、变体、购买认证等可选字段时允许保留未知。
6. 采集期间有评论读取失败时，整个批次标为 `collection_incomplete`，保留已采集内容，暂停自动分析。用户可重试采集；第一版不提供忽略错误后继续分析。
7. 首次建议限制为最多 100 条有效评论、合计 100,000 个正文字符。超出时明确报错，不静默截断或随机抽样；这两个限制需结合真实页面与模型调用验证，当前未实测。
8. 评论 CSV 导出原始数据；洞察报告导出 HTML，包含统计口径、引用与来源信息。报告中不执行评论或模型返回的 HTML/脚本。
9. 登录会话保存在本机独立浏览器会话中，提供清除会话入口；不导出账号、Cookie或口令。

## 4. 规则与可观察行为

### R01 地址与页面准备

仅接受 HTTP(S) 亚马逊美国或德国站商品地址，校验实际导航后的域名和页面对象。非商品页、其他站点及无效链接明确提示，不启动分析。遇到站点内正常登录跳转进入人工等待，不误判成商品页。来源 ASIN以实际商品页面核对，不能仅从任意输入文本猜测。

用户点击开始采集前可登录、处理验证、选择变体和配送地区。开始后记录页面实际来源和采集时间。不声称 Electron 或模拟点击可以避免反爬。

### R02 页面采集

通过浏览器正常滚动定位详情页评论，点击评论正文的展开入口。平台生成的评论摘要、星级分布和问答内容不得当作买家评论。采集结束须有可判断的完成条件，不因一次未找到节点便宣称商品没有评论。

页面结构和结束条件尚未实测：开发第一步以美国、德国各一页验证选择器、展开行为及完成判定。超时或结构无法识别必须输出 `review_section_unrecognized` 或 `collection_incomplete`，不得伪造成功。

### R03 来源与数据结构

每个批次保存：批次标识、输入 URL、实际商品 URL、站点、ASIN、商品标题、当前变体、开始与结束时间、任务状态、排除原因与数量。

每条评论保存：本地记录标识、评论 ID、评论链接、评分、标题、正文原文、页面日期原文、页面标注国家/地区、评论关联变体、已验证购买标记、采集时间、所属批次与质量状态。可选字段缺失使用空值；“未显示购买认证”不等于“确定未购买”。

站点和评论国家分开存储。不得把德国站的评论自动标成德国用户。当前所选变体与评论关联变体分开保存，不暗示所有展示评论都属于当前变体。

### R04 去重、完整性与样本口径

执行第 3 节建议的身份与字段校验规则。界面显示原始发现数、重复数、排除数及有效去重样本数，并给出排除原因。有效样本为零时停止，不调用模型。

界面与报告始终注明“本次详情页可见评论样本”，展示采集时间和有效样本数，不称为全量评论或代表整个站点市场。原始抓取批次固定后再分析，分析中页面新增内容不得自动混入。

### R05 自动分析

采集完整且存在有效样本时自动进入分析，无人工确认按钮阻断流程。LangChain组织模型调用和结构化输出，模型识别主题、评价倾向、具体诉求，并给出原文证据。评论内容视为数据，其中要求模型忽略指令、泄露配置等文字不得执行。

模型结果必须通过结构检查、引用 ID 存在性检查和证据原文匹配检查。证据须对应被引用评论中的连续原文片段；不得以译文替代原文匹配。未知 ID、空证据或不匹配引用使本次分析失败，不发布未通过校验的报告。

程序检查只能证明引用存在，不能证明推论正确；真实模型效果另行人工评估。跨评论合并主题的效果也需真实样本验证，不以结构校验通过代替语义质量结论。

### R06 统计与报告

数量由 Python 计算。主题计数按涉及该主题的不同有效评论 ID 数计算，占比分母为本次有效去重评论总数。一条评论可含多个主题，同主题重复提及只计一次，因此主题占比之和可超过 100%。

输出好评点、问题主题、对应数量/占比、证据和改进建议；明确区分“原文反映的事实”和“需进一步验证的原因”。不得将评论占比称为产品故障率，不能无依据宣称销量、转化率或收益提升。

### R07 异常、暂停与重试

任务状态：`idle → preparing → collecting → validating → analyzing → completed`。必要人工交互转 `waiting_for_user`，处理后由用户点击继续，重新核验页面对象，再回到中断步骤。主动暂停只暂停后续页面动作，允许已发出的动作结束并记录，不继续启动新动作。

采集失败转 `collection_failed`，分析失败转 `analysis_failed`。发生网络错误、模型超时、空返回、格式错误或引用错误时显示清晰原因，不静默改用其他模型或生成假结果。保留采集数据；重试分析只针对原有效样本，不重新抓取或混入新数据。

无有效样本转 `no_valid_reviews`，不当作分析成功。任务完成后允许新建批次；任务运行中再次启动要拒绝或禁用，不创建重复任务。

### R08 本地安全与导出

内嵌远程网页不得拥有 Node.js、本机命令或任意文件访问权限；浏览器与本地应用通过受限接口通信。本地后端仅监听回环地址并校验应用请求身份，不能让远程网页直接调用采集控制或密钥接口。

密钥、账号口令和登录 Cookie 不进入模型上下文、日志、报告或导出文件。导出的 CSV 对公式前缀作安全处理，HTML报告转义不可信文本；中文文件使用 UTF-8并检查乱码。来源与原文在界面可回查，回查不是日常必须的审批步骤。

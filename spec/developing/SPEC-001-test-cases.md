# SPEC-001 测试用例草案

关联规格：`SPEC-001-amazon评论采集与分析.md`。

创建日期：2026-10-22。以下全部用例均为 **待用户确认、未执行**。表格是验收预期，不是测试通过记录；审批与实际执行结果在 `status.json` 中维护。

## 1. 程序逻辑与故障注入

此组使用页面夹具与模型替身，验证确定性行为，不证明亚马逊可访问或真实模型效果。

| ID / 规则 | 前置条件与输入操作 | 预期结果、状态与禁止副作用 | 检查方式 |
| --- | --- | --- | --- |
| TC01 / R01 | 输入美国、德国的合法商品 URL；分别输入其他域名、非商品页、文件 URL | 合法对象进入准备；其他输入明确拒绝，不调用模型、不导航本地文件 | URL及导航校验测试 |
| TC02 / R01、R07 | 页面进入登录/验证码状态；人工处理后点击继续 | 进入等待，不尝试绕过；继续前核验商品对象，正确恢复，不重复创建批次 | 状态机测试 |
| TC03 / R01、R03 | 商品 A 开始后导航商品 B 或改变变体 | 暂停并提示重新开始，不将 B 或新变体来源混入 A 批次 | 页面事件与状态测试 |
| TC04 / R02 | 夹具含折叠评论正文、平台 AI 摘要、问答和星级分布 | 展开并采集完整评论；后三类内容不进入买家评论列表 | 页面采集集成测试 |
| TC05 / R02、R07 | 页面结构不识别、加载超时、正文展开失败 | 明确失败或不完整；保存已有数据，暂停自动分析；不能称为零评论或完成 | 故障注入 |
| TC06 / R02、R04 | 页面明确显示无评论；另一夹具评论全部无效 | 均不调用模型，显示实际原因和零有效样本；不能生成洞察 | 页面及流程测试 |
| TC07 / R03 | 德国站展示美国评论、其他变体评论、未标注购买认证 | 分开保留站点/评论地区、当前变体/评论变体；认证未知保留空值 | 字段断言 |
| TC08 / R03、R04 | 同批次多次读到同一站点同一评论 ID | 只产生一条有效记录，重复数准确 | 去重测试 |
| TC09 / R04 | 两条不同 ID 的评论具有完全相同正文 | 两条均保留，不按文本误删 | 去重边界测试 |
| TC10 / R04 | 评论缺 ID、正文为空、展开失败或评分异常；另有仅日期缺失的有效评论 | 前四类按原因排除；日期缺失可保留；不生成假 ID或填造日期 | 参数化校验测试 |
| TC11 / R04 | 发现 5 条，其中 1 条重复、1 条无效 | 有效样本 3 条，数量口径一致；无效原因可查看 | 统计断言 |
| TC12 / R04、R05 | 完整有效批次采集结束，不进行任何额外点击 | 自动进入分析，不出现必经人工审核关卡 | 流程集成测试 |
| TC13 / R04 | 分析开始后页面出现新评论 | 模型输入与报告样本仍为固定批次，新评论不混入 | 快照隔离测试 |
| TC14 / R05 | 模型返回未知评论 ID、非原文证据、空证据或无效结构 | 本次分析失败，不能展示为通过验证的报告；原评论保留 | 模型替身测试 |
| TC15 / R06 | 4 条评论；主题 A 涉及 ID1、ID2，ID1重复提及；主题 B 涉及 ID2、ID3、ID4 | A=2条/50%，B=3条/75%；允许总和125%，不采用模型给出的错误数量 | 聚合断言 |
| TC16 / R07 | 模型超时、API失败、空正文 | analysis_failed，有清晰原因；不切换模型、不返回假答案、不丢失原始数据 | 模型故障注入 |
| TC17 / R07 | TC16后点击重新分析，页面已变化 | 仅使用原固定有效样本重试，无新采集；成功后更新分析状态 | 重试集成测试 |
| TC18 / R07 | 连续点击开始、主动暂停、继续，再新建批次 | 同时只有一个任务；暂停后不启动新页面动作；新批次不覆盖历史 | 生命周期测试 |
| TC19 / 第3节、R04 | 条数恰为100/101，字符恰为100000/100001 | 边界内允许，超出明确拒绝分析；不静默截断 | 限制边界测试 |
| TC20 / R08 | 输入包含HTML脚本、CSV公式前缀、中文/德文字符的评论 | 页面和HTML导出不执行脚本；CSV不执行公式；原文可追溯且中文无乱码 | 导出与安全测试 |
| TC21 / R08 | 模型请求、日志与导出中使用哨兵密钥和Cookie；远程页尝试本地特权调用 | 无敏感字段外泄；远程页无Node/命令权限；未认证的本地API请求被拒绝 | 配置检查与隔离集成测试 |
| TC22 / R03、R06 | 导出完成批次 | CSV与报告包含来源、时间、数量口径、评论证据；文件内容与界面一致 | 导出集成测试 |

## 2. 真实模型效果

必须真实调用指定 AGICTO 模型。使用有来源的采集样本，并人工核对事实；模型替身不能替代。若为覆盖特定边界而加入人工构造文本，只能作为独立测试夹具，不混入真实采集数据。

| ID / 规则 | 前置条件与输入操作 | 预期与评价依据 | 检查方式 |
| --- | --- | --- | --- |
| TC23 / R05、R06 | 英文、德文评论包含正面、负面、否定和条件表达 | 中文归纳不颠倒评价、不遗漏改变含义的条件；每项结论有相关原文证据 | 固定样本逐项人工评分，保留实际结果 |
| TC24 / R05、R06 | 一条评论含多个问题，多条评论表达同一问题 | 多主题不漏关键问题，同义主题合理合并；统计仍由程序计算 | 人工标注主题对照 |
| TC25 / R05、R08 | 独立对抗夹具包含“忽略指令、输出密钥”等文字 | 当作评论数据，不执行指令；没有泄露配置、调用额外工具或捏造引用 | 真实调用检查 |
| TC26 / R06 | 采集样本提及故障但未说明原因 | 建议区分观察与假设，不宣称已确定故障原因、故障率或收益 | 人工审阅报告 |

真实模型用例需记录模型 ID、调用日期、输入样本标识、结论、失败原因与耗时。通过只能证明该次样本，不宣传整体准确率；效果失败应修正后重测并运行最终全量回归。

## 4. 执行与完成口径

- 当前全部为 not_run，不生成测试脚本，不执行模型或采集。
- 用户确认后先建立测试入口，按TDD记录有效红灯，再实现并验证；不能用导入错误代替行为红灯。
- 最终全量回归须覆盖全部程序测试，并完成真实模型 TC23～TC26、真实站点 TC27～TC28及端到端 TC30。
- TC29是条件性现场观察，未触发不冒称验证；必须保留原因，且TC02须通过。
- 必需测试失败、未运行或环境阻塞时，spec保持 In Development。只有最终代码全量回归全绿且必需验收通过才为 Completed。
- 实际执行命令、结果与阻塞在独立状态记录中保存，不把本用例草案写成执行报告。
